Treap (Tree + Heap)

A Treap is a combination of Binary Search Tree and Heap. It maintains both BST property and Heap property.

Learn More ↓

What is Treap?

A Treap is a randomized balanced binary search tree. Each node contains:

1️⃣ Key (BST Property)

Left subtree contains smaller values. Right subtree contains larger values.

2️⃣ Priority (Heap Property)

Parent node priority must be greater (Max-Heap) or smaller (Min-Heap) than its children.

Treap Structure Example

         (50, 90)
         /      \
   (30, 70)    (80, 60)
     /
 (20, 50)

Format: (Key, Priority)

Treap Operations

Insertion

1. Insert like BST using key.
2. Rotate to maintain heap property.

Deletion

1. Rotate node downward.
2. Remove like BST delete.

Search

Same as Binary Search Tree search operation.

Rotation

Left Rotation and Right Rotation maintain heap property.

Time Complexity

Operation Average Case
Search O(log n)
Insert O(log n)
Delete O(log n)

Why Do We Need Treap?

Problem in BST

Normal BST can become skewed and degrade to O(n) time complexity.

Balancing Issue

Maintaining balance manually (AVL / Red-Black) is complex.

Treap Solution

Random priorities automatically maintain expected O(log n) height.

Treap Insertion Pseudocode

function insert(root, key):
    if root == NULL:
        return new node(key, random priority)

    if key < root.key:
        root.left = insert(root.left, key)

        if root.left.priority > root.priority:
            rotateRight(root)

    else:
        root.right = insert(root.right, key)

        if root.right.priority > root.priority:
            rotateLeft(root)

    return root

Important Theoretical Notes

🔹 A Treap is also called a Randomized Binary Search Tree.

🔹 It combines two fundamental data structures: Binary Search Tree and Heap.

🔹 The key maintains the BST property while the priority maintains the heap property.

🔹 If priorities are assigned randomly, the expected height of the treap becomes O(log n).

🔹 Treap performance is probabilistic, not strictly guaranteed like AVL or Red-Black Trees.

Mathematical Insight

📌 Expected Height of Treap:

E(height) = O(log n)

📌 Worst Case Height:

O(n)

📌 Reason: If priorities are random, probability of skewed tree is very low.

This makes Treap highly efficient in practical applications.

Advantages of Treap

  • ✔ Self-balancing structure
  • ✔ Simple implementation compared to AVL/Red-Black Tree
  • ✔ Efficient average-case performance
  • ✔ Used in Competitive Programming
